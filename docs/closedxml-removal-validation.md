# ClosedXML removal validation

This implementation removes the legacy Reader and Mapping writer, all active
ClosedXML package dependencies, and their test/tool usages. Both defaults are
OpenXml; Auto uses that same path without fallback. Numeric enum value 0 remains
obsolete and produces an early migration error. The public style converter API
changes to `Convert(CellStyleInfo, CellValueType)`.

Baseline: `feature/openxml-integration`, commit
`24c9dea4d67190951d152eef56f76abc943ef733`. The initial validation below used the
uncommitted `feature/remove-closedxml` working tree, before any remote push,
release or package publication. Source/fixture hashes for that snapshot are recorded in
[the source inventory](validation/closedxml-removal/source-inventory.json).
Environment: Debian 13 linux-x64, .NET SDK 10.0.401, runtime 10.0.12.

## Regression and structure

From the repository root:

```bash
dotnet restore ExcelRenderer.slnx --force-evaluate
dotnet build ExcelRenderer.slnx -t:Rebuild --no-restore --verbosity:minimal -m:1
dotnet test ExcelRenderer.slnx --no-restore -m:1
python scripts/check-core-dependencies.py
```

The final Rebuild has zero warnings/errors. All **1,002 tests pass**, with no
skips: Core 80, Mapping 146, OpenXml 154, full library 538 and Tool 84. Current counts and command results are recorded in
[acceptance.json](validation/closedxml-removal/acceptance.json); raw logs are in
[rebuild.log](validation/closedxml-removal/rebuild.log) and
[tests.log](validation/closedxml-removal/tests.log). The standalone Core validation
and reference projects are also rebuilt independently.

The parent passed 917 tests. Its 15 sample workbooks supply fixed model and
PNG/SVG/Markdown goldens, with invariant culture and the pinned repository
NotoSansJP regular font. SVG resource IDs are normalized. PDF byte hashes are
avoided; existing PDF geometry/font/resource checks remain active. Raw source
projections from the original OpenXml reader are retained separately and compared
without loading the removed library. All recorded inputs have matching hashes.

Complex test inputs were captured from the parent's builders before later SDK
mutations. They are immutable fixtures, not regenerated by the new reader.
[Provenance and byte hashes](validation/closedxml-removal/retained-fixture-provenance.json)
identify the original test/member and capture script. Simple/dynamic fixtures use
SDK elements. There is no compatibility workbook API or test-only legacy package.

Mapping tests cover scalar values, CLR/JSON, styles, dates/durations, escapes,
nested/empty arrays, once-only evaluation, cancellation/spill cleanup, row metadata,
merges, print areas/titles, manual/directive breaks and atomic file output. Forty
cases compare ten parent fixture features, zero/three items and OpenXml/Auto:
static names, internal/external links, pictures, comments/VML, tables/filter and
conditional formatting/validation. Cross-sheet quoted names, mixed references,
string literals/function names, deleted/single-cell/full-height print areas,
missing relationships, unknown drawing extensions and direct-writer restrictions
are checked separately. New or duplicated comment/drawing IDs are validated.

Four additional parent pivot cases expose stale source addresses and placeholder
cache records in the previous writer. The replacement moves flat worksheet
sources and pivot locations, rebuilds changed records/shared items and requests
pivot refresh. It does not calculate pivot aggregate cells. Unchanged pivot parts
retain their decompressed bytes. Sparkline extensions retain the parent's common
formula-preflight rejection. Grouped/calculated/external or unresolved named pivot
sources and other unsupported parts remain explicit preflight failures. See
[the compatibility ledger](closedxml-removal-compatibility.md) for the exact scope.

Known structural corrections and equivalent representations are explicit:
internal links follow the referenced row, print areas include every occurrence,
and pivot caches no longer retain mapped placeholders. CF/DV coverage is compared
as source cells, rather than requiring identical range partitioning. Empty comment
parts may be retained. Original media bytes are preserved. These are not broad
fixture-level waivers.

The whole-book formula ban still precedes data access, including hidden/deleted
cells, shared/array/data-table formulas, table formulas/totals functions and computed
names. Saved Reader results remain unchanged (including stale 99 versus calculated
52, missing/zero/false/empty/error distinctions). No evaluator was introduced.
Original `calcPr`, including its absence, is preserved without formula calculation
requests. Existing source diagnostics and strict/warnings-as-errors behavior remain.

## Dependencies and distribution

```bash
dotnet pack ExcelRenderer.slnx --no-restore --verbosity:minimal -m:1 -o /tmp/excelrenderer-removal-packages
python scripts/check-closedxml-removal.py \
  --packages /tmp/excelrenderer-removal-packages \
  --output /tmp/removal-inventory.json
```

The audit checks all 16 restored project graphs and locks, active C# sources,
built dependency manifests and five local packages: main, OpenXml, Mapping, Fonts
and Tool. ClosedXML, ClosedXML.Parser, RBush, SixLabors.Fonts and XLParser are absent.
ExcelNumberFormat remains required by OpenXml. Core remains nonpackable; main and
Tool each ship exactly one Core DLL/XML, with identical Core DLL hashes.
[The inventory](validation/closedxml-removal/dependency-and-package-inventory.json)
records package hashes and manifests checked.

An isolated project consumes only the local main/Mapping packages, uses the new
style API, renders PDF/PNG/SVG/Markdown, invokes Core PDF and maps an invoice before
rendering every format. Assembly references and loaded assemblies contain no
ClosedXML. A freshly installed local Tool package generates XLSX and all four
formats. Deprecated reader/mapping CLI options fail before missing inputs/data
are read and preserve output sentinels. The installed OpenXml DLL hash is checked
against the audited nupkg. Consumer source/configuration and raw results are retained.
These existing-version packages are local verification artifacts, not releases.

Six SDK schema errors already exist in the sample invoice template's font records;
the mapped invoice retains exactly those descriptions and adds none. This inherited
input issue is recorded explicitly. Structural fixtures are checked for new schema
errors against the parent. All 16 newly SDK-generated performance fixtures have
zero schema errors; see [tool-schema.json](validation/closedxml-removal/tool-schema.json).

## Performance and evidence scope

Reader, Mapping, rendering and Mapping-plus-rendering comparisons run the original
parent-default and parent-OpenXml binaries separately from the replacement.
Inputs, culture (en-US) and the NotoSansJP font are identical. Each sample runs in
a fresh process, with one discarded warmup and three measured samples. Fixture
generation is excluded; runs start after builds and regression tests finish.
Mapping value/merge projections must match across implementations.

[Reader samples](validation/closedxml-removal/reader-performance.json) and
[Mapping/render samples](validation/closedxml-removal/mapping-render-performance.json)
record timing, allocation, peak RSS, counters, input/font hashes and all samples.
Debug builds and small synthetic inputs are used; peak RSS includes runtime/JIT
startup. Results are measurements on this host, not general speed guarantees.
Elapsed-time medians (milliseconds):

| Input / operation | Parent default | Parent OpenXml | Removal |
| --- | ---: | ---: | ---: |
| Reader, 1,000 × 20 cells | 2393.6 | 1554.3 | 1373.9 |
| Plain Mapping, 1,000 items | 740.8 | 360.9 | 392.5 |
| Nested Mapping, 1,000 output rows | 827.5 | 381.0 | 401.9 |
| Geometry Mapping, 1,000 items | 1585.6 | 426.5 | 424.4 |
| Render, 100 rows | 2086.1 | 1126.1 | 988.1 |
| Mapping + render, 100 rows | 3013.2 | 1182.3 | 1252.5 |

Compared with the old default, these Mapping cases reduce elapsed time and
allocation. Compared with the parent's explicit OpenXml path, plain/nested Mapping
are approximately 5–9% slower and allocate about 2 MiB more; Mapping + render is
approximately 6% slower and allocates 1.5 MiB more. The expanded structural and
relationship checks add work. Reader and standalone rendering reduce time and
allocation in these samples. No threshold or universal improvement is claimed.

A separate nested-mapping smoke benchmark verifies values, types, row heights,
styles and merges; formula rejection verifies zero output bytes.

Historical `reader-phase-ab-*` files retain the earlier partial migration evidence.
They do not describe final dependency/package acceptance. Parent logs and generator
sources remain historical provenance and are excluded from active project graphs.

## CI follow-up — 2026-10-16

The first PR run stopped in the mutation checks: the EMU and marker mutations
still targeted the DOM picture parser, while the existing anchor tests now read
pictures through `CoreExcelReader.OpenXml.cs`. Both mutation harnesses now alter
that active shared parser. The original numeric expectations remain unchanged.
All 19 output mutations, four Core mutations and two shared geometry mutations
are detected, and the harnesses restore the original source bytes.

The subsequent visual check exposed a changed comparison input. The SDK
normalizer does not reproduce incidental ClosedXML save changes, including
literal header/footer font-control strings. Nine normalized inputs were captured
with the unmodified parent validation tool and retained in
[Baselines/Inputs](../tests/ExcelRenderer.Core.Tests/Baselines/Inputs/README.md),
with original sample, generator source and captured input hashes. The visual
harness validates both input hashes before rendering the fixed inputs. All 17
pages match the existing golden rasters exactly (maximum baseline MAE 0); the
maximum Core/main MAE is 0.000362245. No golden image or threshold was changed.

Follow-up verification used locked solution restore, a Release Rebuild (zero
warnings/errors), all 1,002 tests (zero failures/skips), the three mutation
harnesses and `validate-core.py --visual-only`. The dependency audit still passes
for all 16 restored project graphs and 36 built dependency manifests; the retained
XLSX files introduce no active dependency on the removed library.
