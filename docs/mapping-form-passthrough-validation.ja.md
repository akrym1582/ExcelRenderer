mapping は `--formula-mode recalculate`、通常版 PDF は標準設定、Core は
NotoSansJP-Regular.ttf を明示指定した。

印刷設定などの保持を検証した。styles、グラフ、画像、プリンター設定、外部リンクなど

## 月次 KPI 報告書の右余白

先頭シートは A4 横、左右 36pt、上下 32.4pt の余白、縦横 1 ページの指定。
元データの高さは 609pt、印刷可能な高さは約 530.48pt のため、縦横とも約 87.1% に縮小する。
標準フォント Calibri 11pt の実体がない環境では既定の MDW 7px が使われ、列幅合計は
縮小前 724.5pt、縮小後約 631.08pt となる。

先頭ページの罫線範囲の左右端は、通常版が約 36.0–667.08pt、
LibreOffice が約 35.95–686.84pt。左端はほぼ同じで、通常版は約 19.8pt（約 7mm）狭い。
大きい右余白の主因は縦 1 ページへの比例縮小と左寄せであり、左端の移動ではない。
LibreOffice の再保存では自動行高の変化も確認した。両者の幅差には基準フォントの
代替・列幅の測定・自動行高の相違が残り、今回、位置や列幅の計算は変更していない。

## 残る差と変更範囲

未知のグラフ等を mapping 出力へ保持しても、その描画機能が追加されるわけではない。
Core の単一フォント、条件付き書式・文字回転・図形などの対応範囲、およびページを
またぐ画像の制約も従来どおり。08/16 の一部ヘッダーではフォント制御コードが表示される。
行の繰り返し・挿入・削除を伴う mapping は未知メタデータの対応範囲検査を維持する。
Core の明示フォントと低水準 PDF API のフォント形式検証も維持する。
