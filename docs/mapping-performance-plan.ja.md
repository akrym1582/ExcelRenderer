# Mapping 性能改善の調査と実装計画

2026-10-09、対象コミット `22a101fd39fa5eb515ff9b1b8ed3d967c5af74e6`。
[前回の計測](mapping-performance.ja.md)を起点に、段階別の計測と隔離した試作を行った。
調査時点では本体の `src` / `tests` は変更していない。以下は当時の実装計画である。
後続の本体変更と検証結果は [実装検証レポート](mapping-performance-validation.ja.md) を参照。

## 決定した対応範囲

ユーザーの指定により、**繰り返し領域内の数式と、その領域に重なる定義名は非対応にする。
繰り返しの外側の数式・定義名は維持する。**

- 単純な `items[*]` の1行展開と、明示的・ネストのブロックに同じ制限を適用する。
- 範囲内の数式を評価結果の値に置き換えたり、黙って削除したりせず、元のセル位置を示すエラーにする。
- 定義名は、ワークブック／シートの定義位置ではなく参照先で判定する。
  行単位の繰り返しなので、本文の右側の列でも同じ行帯に重なる範囲名は対象になる。
- 配列が空の場合も、元テンプレートの検証で数式・重なる定義名を拒否する。
- 外側のフッターの数式、外側のセルを指す名前、別シートの数式などは維持する。
  外側から繰り返しのセルを参照する数式も、セル自体が外側なら許可する。
- 印刷範囲・印刷タイトルはページ設定として維持する。ユーザーの定義名と混同して拒否しない。
- mapping のエイリアス `@order` / `@line` は維持する。Excel の定義名とは別の機能。

数式の計算が必要な明細は、C# / JSON 側で値を計算して渡す。
これは既存の対応機能の縮小なので、英語・日本語の mapping ガイドとリリースノートへ明記する。
公開 API と `netstandard2.1` は維持するが、既存の繰り返し内数式を使うテンプレートは移行が必要。

## 結論と原因

改善余地は大きい。反復する行削除をなくし、最終行へ必要なセルを配置する方式を主案にする。
数式の複製互換性を扱う必要がなくなるため、単純配列・明示的ブロック・ネストを
同じ配置計画へまとめる方針を取りやすい。

| ケース | 呼び出し全体 | 主な処理 | 主な処理の時間 | 主な処理の割当量 |
| --- | ---: | --- | ---: | ---: |
| 明示的ブロック300件 | 3.68秒 | 行削除600回 | 3.36秒（約91%） | 約11.9 GB |
| ネスト・子1,000件 | 8.47秒 | 行削除2,200回 | 7.72秒（約91%） | 約28.5 GB |
| 単純 CLR 配列1万件 | 1.83秒 | 行の複製 | 1.21秒（約66%） | 約1.29 GB（全体の約90%） |

ブロック300件の値の評価・計画は約7 ms、保存は約27 ms。
単純配列1万件の計画は約63 ms、保存は約309 ms。
CLR のメンバー取得や JSON 解析より、まず展開方法を変えるべき結果だった。

元実装を `/tmp/excel-mapping-study/baseline` に複製し、読み込み、解析、計画、
展開、保存、出力コピーを計測した。Release、新しいプロセス、逐次実行で比較した。
複製・削除の時間は展開の時間に含まれるので、合算しない。
段階別の割当量は実行スレッドの累積値、呼び出し全体は全プロセスの累積値。
GB は10進表記で、いずれも同時に保持するピークメモリではない。

## 試作で確認した効果

各試作は本体とは別のディレクトリで作成した。以下の試作値は各1回。
計測用の処理を追加しており、製品の性能保証ではない。

### マーカーを最初に1回だけ除く

ネストのないブロックの開始・終了行を、本文の複製前に1回ずつ削除した。

| ケース | 元実装 | 試作 |
| --- | ---: | ---: |
| ブロック300件 | 3.68秒・削除600回 | 0.32秒・削除2回 |
| ブロック1,000件 | 前回64.55秒 | 0.56秒・削除2回 |
| ブロック1万件 | 今回は未測定 | 2.01秒・削除2回 |
| ネスト・子1,000件 | 8.47秒 | 2.23秒 |
| ネスト・子1万件 | 前回90秒で打切り | 今回も90秒で打切り |

これは短期の改善案として有効。ただしネストの親ブロックの構造変更は残るため、
最終案には、次の最終行配置を採用する。

### 値・書式だけの行をセル単位で書く

元行の使用セルの値・書式を一度保存し、挿入済みの行へ書く試作を行った。
行高・非表示・アウトライン・行スタイルのコピーは維持した。
数式・結合・条件付き書式・入力規則・コメント・リンク・リッチテキスト・
スパークラインなどは、この試作では汎用コピーに戻した。

| ケース | 元実装 | セル単位コピーの試作 |
| --- | ---: | ---: |
| CLR 1万件 | 今回1.83秒・約1.33 GiB割当 | 1.41秒・約0.25 GiB割当 |
| CLR 99,998件 | 前回中央値10.66秒・約13.4 GiB割当 | 4.97秒・約2.37 GiB割当 |
| ブロック1万件 | マーカー改善だけで2.01秒 | 両方の改善で1.27秒 |

99,998件のピーク working set は、前回488〜496 MiBから試作402 MiBになった。
割当量の削減ほどピークは下がらない。展開後の workbook と全行の計画を保持するため、
一定メモリのストリーミングにはならない。

### ネストを最終行配置に平坦化する

評価済みのブロックの木を「最終出力行の並び」に変換し、元行のスナップショットから
直接配置した。マーカー行を大量に複製せず、構造変更もまとめた。

| ケース | 元実装 | 最終行配置の試作 |
| --- | ---: | ---: |
| ネスト・子1,000件 | 今回8.47秒 | 0.38秒 |
| ネスト・子1万件 | 前回90秒で打切り | 1.23秒 |
| ブロック1万件 | 元実装は今回未測定 | 1.31秒 |
| CLR 99,998件 | 前回中央値10.66秒 | 4.57秒・約2.02 GiB割当 |

ネスト1万件の展開は約448 ms、累積割当は呼び出し全体で約0.23 GiBだった。
行数、先頭・末尾の値、末尾数値、フッター、背景色、行高の再読込検証に成功した。
この試作は **数式・定義名・結合などを持たない workbook に限定** している。
外側の数式や定義名を維持する本番設計を完成させた結果ではない。
これらを含むケースは、領域単位の更新と追加の回帰検証が必要。

### 右端結合の欠落を修正する

`TemplateSheet.LastColumn` に結合範囲の右端も含めると、右側にダミーのセルを置かずに
2件・1万件とも結合数の検証が成功した。1万件を正しく出力すると約11.96秒。
元の約2秒の失敗ケースは結合をほとんど複製していないため、正常な性能の比較対象にはしない。
複製が約10.93秒・約17.5 GBの割当を占め、結合の一括配置にも改善余地がある。
最終行配置の試作では結合を高速処理の対象にしていないので、ここは追加検証する。

## 数式を非対応にする判断の根拠

マーカーを先に除く試作では、ブロック内から外側を指す相対数式が変わった。

```text
A1: Header
A2: **@start-array items[*] as item
A3: **@item.value     B3: =A5
A4: **@end-array
A5: 99
A6: 77
```

3件展開の2件目の `B3` は現行では `=A8`・値0、試作では `=A6`・値77。
同じ参照を別シート名付きにしても差が出た。定義名・印刷範囲の今回の比較は一致したが、
すべての参照形の一致を意味しない。

当初の試作は既存32件＋追加5件の37件を通ったが、この相対数式を追加すると
38件中1件失敗した。数式・定義名などがある workbook を既存処理へ戻す試作は38件成功した。
ただし、**今回の合意は workbook 全体での禁止やフォールバックではない**。
本番ではこの `B3` を繰り返し内の数式として拒否するテストへ変更する。
外側の数式と定義名は別の成功テストで維持を確認する。

## 実装順序

| 段階 | 実装内容 | 完了条件 |
| --- | --- | --- |
| 0 | 新しい対応範囲の事前検証と、結合の右端を含む幅の修正 | 繰り返し内の数式・重なる名前を空配列でも拒否。右端結合の検証成功 |
| 1 | 最終行配置を作り、値・書式中心の配列・単純ブロック・ネストを同じ方式で出力 | 反復的な構造変更を除去し、1万件のネストが完了 |
| 2 | 領域単位の更新、外側の数式・定義名・印刷設定の維持、結合・固定条件のルールの配置を完成 | 外側の参照、スタイル、結合、改ページなどの回帰検証に成功 |
| 3 | 計画の保持量、取得方法のキャッシュ、改善後に重くなった保存を再評価 | 同じ正しい出力で、追加の時間・割当・ピークの低下を示す |

段階0を独立した小さな修正にする。段階1・2は共通の配置設計で進める。
途中で速度を改善したケースと、未確認のため既存処理を維持するケースを明記する。
数式の複製をサポートするための大規模な参照変換は、今回の計画から外す。
外側の参照の維持は、段階2の受入条件に残す。

### 事前検証

- `TemplateSheet` の解析時に、繰り返す行帯の `HasFormula` を検査する。
  暗黙の1行配列でも、別の列にある数式を見落とさない。
- 元の数式セルのアドレスと `=...`、名前の場合は名前と参照範囲を診断に含める。
  `WorksheetExpansion.Apply` と出力書き込みの前に検証する。
- ワークブック／シート両スコープの定義名について、対象シート・行帯との重なりを調べる。
  外側の固定範囲名・定数名は維持する。名前が別名を参照するケースも検証する。
- 動的参照など、名前の範囲を確定できないものは初期の高速化対象から除き、
  外側の既存の機能を無言で失わないようにする。判定不能な名前の対応範囲を明記する。
- 条件付き書式・入力規則の参照式も同じ問題を持つため、繰り返し内で非対応にする案を
  実装前に整理する。セル数式とは別の制限として明記し、数値・固定リストなど、
  参照式のないルールは維持を検証する。

### 最終行配置と外側の維持

1. 各出力行に「元の行番号・最終行番号・評価済みの値」を持たせる。
   親子ブロック、親エイリアス、固定行、空配列を同じ配置計画にまとめる。
2. 全データの検証と最終行数の上限確認を終えてから workbook を変更する。
   getter や IEnumerable を二度評価せず、元セルの診断と出力保護を維持する。
3. 繰り返し領域のセル・行属性・結合・ルールを変更前に保存する。
   元 workbook を丸ごとクリアして再構築する試作を、そのまま本番へ入れない。
4. 元シートを維持し、トップレベルの領域ごとに必要な行変更をまとめる。
   元テンプレートのマーカー除去と最初の要素の配置を使い、外側の参照先を保つ。
   要素ごとにマーカー付きブロックを挿入・削除する方式には戻さない。
5. 最終位置へ値・スタイル・行属性と結合・ルールを書き、元行との対応で改ページを設定する。
   外側のセルの数式・名前などは、ClosedXML の行操作による更新と比較検証で維持する。

外側から、本文の先頭・途中・末尾、別ブロック、別シート、フッターを参照するケースを比較する。
ネストの最初の子配列が空のケースも、参照先が異なるデータを指さないことを確認する。
行操作をまとめるだけで外側の参照が正しくなるとは仮定しない。
初期実装で確認できない外側の参照形は既存処理を維持し、機能を失わない。

### 後順位の最適化

- 各行の値を列数が分かる配列で保持し、List の拡張と余剰容量を減らす。
- CLR の取得方法を型・名前単位でキャッシュする。値はキャッシュせず、型保持と大小文字の仕様を維持する。
- Dictionary は Ordinal 比較が確認できる場合だけ直接検索する。大小文字を区別しない Dictionary の拒否テストも維持する。
- 配列の実体化中にもキャンセルを確認する。ClosedXML の単一の保存処理の即時中止は保証しない。
- 保存用ストリームの小さな削減より、workbook と評価済み計画の保持量を先に確認する。

最終行配置の99,998件では、保存が約2.19秒（全体4.57秒の約48%）になった。
展開を改善した後は、保存と計画の保持も次の負荷として調査する。
外側に数式がある場合の保存前評価は維持する。既定で評価を無効にして描画の計算値を変えない。
OpenXML のストリーミング書き込みへの全面移行は、Excel 機能の移植が大きいため独立した後続検討にする。

## 失敗した検証と回帰テスト

| 対象 | 修正・テスト方針 |
| --- | --- |
| 右端結合が1つしか残らない | 幅を修正し、2〜3件で全結合アドレス・値・書式を検証。ダミーセルは不要 |
| ネスト1万件が未完了 | 最終行配置で構造変更をまとめ、親件数・子件数を別々に増やして測定 |
| 繰り返し内の数式 | 生成成功のテストを、空・1件・複数件でも拒否し出力を保護するテストへ変更 |
| 繰り返しに重なる定義名 | 両スコープ、本文・マーカー・本文外の列への名前を拒否するテストを追加 |
| 外側の数式・定義名 | フッター移動、別シート参照、本文の参照、複数領域、空の子配列で成功を検証 |
| 検証失敗の情報が途中で途切れる | 期待・実際の範囲、失敗セル、mapping 完了の有無、終了コードを構造化して保存 |

既存の `Single_row_arrays_preserve_styles_merges_formulas_and_following_rows` は、
数式なしの書式・結合・フッター・印刷設定のテストと、内側数式の拒否テストへ分ける。
`Multirow_blocks_preserve_vertical_merges_formulas_hidden_rows_and_validation` も、
縦結合・非表示・固定条件の入力規則を維持する成功テストと、数式の拒否テストへ分ける。

型・カルチャー・null・空配列・親エイリアス・行高・アウトライン・行／列スタイル、
改ページ・複数シート、入力／出力ストリーム保護のテストは維持する。
通常の回帰は小さな入力で再現し、処理時間は xUnit に固定秒数で埋め込まず独立した性能検証にする。

性能検証は同じ入力と同じ環境で、原則3プロセス以上の中央値を比較する。
入力準備・mapping・検証のフェーズを分け、タイムアウト時の進捗も記録する。
JSON の生成は別プロセスへ分けるなど、生成のピークを mapping のピークと混同しない。
小さな回帰では全セル、大量ケースでは全データ行の値・型も検証する。
時間上限を延ばすだけ、検証を省く、失敗ケースを正常扱いにする変更はしない。

## 受入基準

今回と同じCPU 2コア相当・8 GiB・Release・10列での一次目標。
異なる環境ではベースライン比と増加傾向も併せて評価する。達成済みの保証ではない。

| ワークロード | 一次目標 |
| --- | --- |
| 値・書式中心の単純ブロック1,000件 | 2秒以内 |
| 値・書式中心の単純ブロック1万件 | 3秒以内 |
| 単純 CLR 配列99,998件 | 6秒以内、累積割当3 GiB以内、ピークが現行を超えない |
| 値・書式中心のネスト・子1万件 | 10秒以内で完了し、全行検証に成功 |
| 外側の数式・定義名など | 計算値・参照先・範囲が回帰検証に一致 |

ネストは親1,000×子10、親10×子1,000、子数がばらばら／空のケースを比較する。
1万→5万→約10万で時間・割当・ピークの増加を調べる。
結合や外側の数式を含むケースは、正しい出力をベースラインにして別途性能目標を設定する。
確認できない機能を既存処理へ戻す場合も、同条件で有意な退行がないことを確認する。

各段階で全ソリューションの Rebuild（警告0・エラー0）と全テストを実施する。
Tool の描画・数式評価・改ページも回帰対象にする。
パッケージ／プロジェクトファイルを変更する場合は pack も確認する。
