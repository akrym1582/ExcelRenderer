# MS Pゴシック帳票の大きさをLibreOfficeへ近づける補正

2026-11-10、PR #113 の `1987a0fe0c51ff60f2da10c9d9ec4d401183d2d0` を補正前として検証。
利用者の bessi50-2 の比較画像で、通常版・Core が LibreOffice より縦に大きい問題を対象とした。

## 原因と変更

元の Normal フォントは「ＭＳ Ｐゴシック」11pt。元書体がない環境では、従来は
全書体共通の MDW 7px を使っていた。一方、この環境の Calc は Latin 数字を
Noto Sans へ代替し、約 8.4px 相当で列幅を解釈していた。
そのため従来の列幅は狭く、縦横 1 ページへ収める際の縮小が弱くなっていた。
中央配置の有無や、空白セルを追加する処理が原因ではない。

通常版・Core が共通で使う `SourceFontFallbackMetrics` に MS Pゴシックの
決定的な代替寸法を追加した。数字幅 0.572em を twip に丸め、96dpi へ変換する。
11pt は 8.4px、10pt は 7.6px となる。英語名・日本語名・全角表記も認識する。
元フォントの実測と明示 MDW／レイアウトフォント指定を優先し、それ以外の不明書体と
Normal 情報なしは従来の 7px を維持する。代替寸法であることの警告も維持する。
Core に追加フォントや OS 上のフォント探索は導入していない。

参照環境は LibreOfficeDev 26.8.0.0.alpha0。
[Calc の桁幅取得処理](https://github.com/LibreOffice/core/blob/master/sc/source/filter/oox/unitconverter.cxx)
と ODS 再保存時の物理列幅を調査した。幅 3.12 の列は ODS で 0.2728in（19.6416pt）、
今回の補正では Excel のピクセル量子化後 19.5pt となる。
これは利用できない MS Pゴシック本体の寸法を保証するものではなく、参照環境の
代替フォントの挙動へ近づける互換値である。

広がった列幅で固定倍率の帳票も調べ、用紙より大きい結合セルをひとかたまりとして
扱うことにより、結合直前に不要なページ帯が作られる問題も修正した。
用紙内に収まる結合は従来どおりまとめ、用紙を超える結合だけを行・列境界で分割する。
`RenderingFontLegacy` を明示した場合は、過去の出力を保持するため従来の結合セルの
ページ分割も維持する。この互換情報は内部モデル・アダプターで引き継ぎ、公開 API は増やしていない。

## bessi50-2 の実測

元の比較と同じ mapping 後 Excel を使い、各シート縦横 1 ページの設定で
「別紙50」だけを指定して出力した。入力の列幅・行高・印刷設定の書き換えはしていない。

| 測定点 | 補正前 | 通常版・Core補正後 | LibreOffice |
| --- | ---: | ---: | ---: |
| 受付番号の文字サイズ | 8.5964pt | 7.4478pt | 7.4070pt |
| 訪問型サービス（独自）の文字上端Y | 457.15pt | 400.99pt | 401.41pt |
| 変更前：従前の体制の文字上端Y | 636.84pt | 556.67pt | 556.04pt |

比較した文字サイズの差は約 16.1% から約 0.55% へ縮小した。
表の上記測定点の Y 差は約 56–81pt から約 0.4–0.6pt へ縮小した。
全ピクセルの一致を意味せず、受付番号付近の自動行高や備考の折返しなどは差が残る。
PDF のほか、PNG・SVG でも同じ寸法で出力できることを確認した。

## 他の帳票への影響

既出 10 帳票で、元データ（xls は既存の LibreOffice 変換 xlsx）／mapping 後
× 元の印刷設定／各シート縦横 1 ページ
× 通常版／Core の 80 PDF 出力を再実行した。mapping ファイル自体は同じものを使用し、
今回 mapping エンジンの変更はしていない。

| 16dekigata-kanri16 | 2 / 2 / 4 | 1 / 1 / 1 |

元の印刷設定のページ数は mapping の前後で同じ。
bessi50 の通常版・Core は既存仕様で非表示シートも含む全シート出力。
表示シート「別紙50」だけなら両者 1 ページであり、右列の比較でもこれを明示指定した。
右列の全 19 ページは 3 者でページ数が一致した。元の倍率を固定する設定では表のとおり
差が残り、今回すべての帳票のページ数を LibreOffice と一致させたとはしていない。

グラフ描画、Core の一部図形・文字回転・ページをまたぐ画像、および一部ヘッダーの
制御コードなど、従来の表示上の制約も残る。
