## Independent expectations and visual output

[representative.xlsx](representative.xlsx) is generated by the SDK test fixture, not
Excel. [expected-attributes.json](expected-attributes.json) records hand-authored A1
expectations: yellow fill, red font and a 2pt solid bottom border. This is independent
of pixel output. The first sqref is A1:B1, with TRUE as its condition. It is not an
Excel-observed oracle. The corresponding Core read/PDF retains ordinary formatting.

`ConditionalFormattingTests` creates model assertions and actual PDF/PNG/SVG output.
`CommonDrawingCommandsContainEffectiveBackgroundFontAndBorder` asserts the shared
commands; raster checks inspect yellow/red pixels in PNG and independently parsed
SVG. Actual outputs are retained under `artifacts/conditional-formatting/`, including
`conditional-formatting.xlsx`, `.pdf`, `.png`, `.svg`, and `svg-review.png`.
PDF was separately rasterized with pdftoppm for visual review. The three formats use
the shared model and commands, without independent per-format conditional evaluators.

Excel desktop and Windows are unavailable. No DisplayFormat capture or Excel-saved
PDF comparison was performed. Relative/noncontiguous anchors, text/blank coercion,
locale differences and merged-border behavior still need an Excel desktop oracle.
The tests establish implemented, hand-specified semantics, not full Excel equivalence.
Unsupported Phase 1 exclusions remain listed in [the support reference](../../conditional-formatting.md).

## Performance protocol

A detached, unchanged worktree at the base SHA builds the before runtime:
`/workspace/cf-phase1-baseline/tools/ExcelRenderer.Performance/bin/Release/net10.0`.
The after runtime is `tools/ExcelRenderer.Performance/bin/Release/net10.0`.

After all builds, tests and package consumers finish:

```bash
python3 scripts/benchmark-conditional-formatting.py \
  --before /workspace/cf-phase1-baseline/tools/ExcelRenderer.Performance/bin/Release/net10.0 \
  --after tools/ExcelRenderer.Performance/bin/Release/net10.0 \
  --output /workspace/cf-phase1-performance
```

The same harness source is built against each runtime without modifying product
DLLs. Three fresh-process rounds alternate before/after order, each with ten warm-up
and five measured reads. Culture is en-US; only the fixed Noto Sans JP file is supplied.
Metrics include elapsed time, cumulative allocated bytes, process-lifetime peak RSS,
model cells, painted cells, snapshots, candidates and condition evaluations. Product
DLL SHA-256 hashes are checked before/after. Plain workloads contain 100,000 cells;
conditional workloads contain 10,000 rows × six columns. The latter use three cellIs
rules plus a row expression, whole-column variants, sixteen overlapping expressions,
and recalculation of a D-column dependency. Recalculate-disabled still recalculates
display formulas while disabling conditional formatting. For these stress workloads,
MaxEvaluationSteps is explicitly 30,000,000 and MaxCellVisits is 5,000,000 in both
runtime harnesses; production defaults are unchanged. Input/reading/model projection
are measured, not PDF layout/render/save. Warm-up/native cache high-water marks are
included in process RSS. No benchmark runs concurrently with builds/tests/consumers.

## Measured performance

Each table entry is the median of 15 measured reads across three fresh processes.
Allocations are cumulative bytes allocated during one read; RSS is process-lifetime
peak memory, including warm-ups. Neither is a retained-model size.

| No-rule workload (100,000 cells) | Base ms | Phase 1 ms | Time delta | Allocated MiB base → Phase 1 | Peak RSS MiB base → Phase 1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Core cached | 403.32 | 389.22 | -3.50% | 181.921 → 181.921 | 330.45 → 330.40 |
| Main cached | 549.53 | 541.58 | -1.45% | 269.671 → 269.672 | 251.71 → 255.25 |

No-rule allocation changes are +368 bytes/read for Core and +512 bytes/read for
main. Both create zero calculation snapshots. The measured time medians do not
show a 5% regression; these observations are not a universal speed improvement claim.

| Conditional workload (60,000 cells) | Disabled ms | Enabled ms | Allocated MiB disabled → enabled | Peak RSS MiB disabled → enabled | Enabled evaluations |
| --- | ---: | ---: | ---: | ---: | ---: |
| Three cellIs + row expression | 424.20 | 822.91 | 178.299 → 477.737 | 312.34 → 338.40 | 90,000 |
| Whole-column sqref | 415.72 | 864.50 | 178.299 → 477.736 | 312.21 → 338.64 | 90,000 |
| Sixteen overlapping expressions | 433.66 | 1514.48 | 178.385 → 1165.574 | 312.66 → 335.49 | 960,000 |
| Recalculate + dependency cells | 623.27 | 977.99 | 276.157 → 548.634 | 329.00 → 343.92 | 90,000 |

All cached disabled cases create zero snapshots; cached enabled cases create one.
Both recalculation cases create one shared display/dependency snapshot, rather than
a second CF snapshot. Every conditional workload retains exactly 60,000 model cells,
including the whole-column case; no million-row expansion occurs. Every measured
painted-cell/evaluation count matches the independently derived expected counts.
Higher cumulative allocations in the overlap case include transient syntax copies
and rule composition, while its measured peak RSS remains about 335 MiB.

[Raw samples](performance-samples.json) and [summary/provenance](performance-summary.json)
retain all warm-up/measured reads, product hashes, fixture hashes and the identical
harness source hash. The original runtime and complete runnable harness evidence
remain under `/workspace/cf-phase1-performance`. The before runtime is the detached
base worktree; no source/output hash was substituted to make measurements agree.

These measurements cover the default read/model path, not range/page-selection
preplanning, layout, painting or PDF/PNG/SVG save performance. The tests cover those
functional paths, but their performance is not quantified by this benchmark. Excel
desktop compatibility and Windows performance remain unmeasured.
