## フォント拒否理由

PDF候補ごとの形式拒否理由を登録IDで保持し、全候補が使えない場合にファミリー・ファイル・face番号とともに例外へ含める。
変換APIでは `PdfFontResolutionFailed` エラー診断にも同じ理由を保存する。
CFFと可変フォントのそれぞれについて、要求フォントが非対応でも静的TrueType代替があれば文字を含むPDFを生成し、
代替がなければ理由付き例外・診断、成果物0件、出力0バイトとなることを検証した。
同一managerで2回失敗しても理由が消えない。インストール済みCLIの配布検証にも、拒否後の有効な代替による成功を追加した。
Coreの単一フォントAPIとPNG/SVGの形式対応は変更していない。

## ピボット更新漏れの実行再現と修正

[修正前ログ](pivot-before-fix.log) は元のwriter分岐で、新規テスト2件が実際に失敗した結果。
CachedValue/Recalculateの両方でA5の差し込み自体は成功するが、キャッシュの `refreshOnLoad` が未設定のままだった。
これはコード上の推測から、合成帳票での実行再現へ進んだ証拠であり、実帳票での再現を主張するものではない。

未知部品を保持する分岐でも、対応済みピボットキャッシュのレコード・共有項目・参照するピボット項目を更新する。
ピボットごとの対応範囲を判定し、未知のピボット拡張を持つ別キャッシュはバイト単位で保持する。
未知キャッシュが同居しても対応済みキャッシュの更新を妨げないテストを追加した。
プリンター設定のバイト列と倍率75%、共有ID、2つのピボットの選択・軸・フィルター、更新レコードを検証している。
行の削除・増加では未知部品を引き続き拒否し、呼び出し側の出力を変更しない。

これはピボット集計値の計算機能ではない。製品PDFは保存セルを描画する。
LibreOfficeはロード時に更新キャッシュからピボット集計表を生成するため、合成帳票のPDFに集計表が追加される。

## 05-borders の比較契約

[旧通常版・現通常版・現Core・Calcの全ページ](05-borders-contact.png) を確認した。
元の固定倍率100%、左右48pt、列A:C各120pt、D=140.25pt、結合タイトルA1:D1は印刷可能幅を超える。
旧出力はA列だけで最初の横ページを終えていた。新出力はA:Cを1ページ目、Dを2ページ目に配置し、Calc参照の文字所属と一致する。

- 1ページ目：細線（黒）、中線（青）、太線（赤）、上のみ、右のみ、下のみ、タイトル。
- 2ページ目：辺ごとの色と太さ、左のみ。8つのデータラベルは各1回のみ。
- 通常版・Coreそれぞれ19本の物理罫線の端点・色・太さと9個の塗り矩形を、元セル寸法から独立に算出して検証。
  [独立監査](borders-pagination-audit.json) は0.002ptで照合する既存罫線監査と同じ精度。
- 位置・字形・全描画・画像・リンク・全画素を144/288dpiで厳密比較する契約は維持。
  欠字・欠罫線・3pt移動を入れた05-bordersの追加変異も検出した。
- [過去のmanifest/PDF](../../../tests/Shared/LibreOfficeComparisonBaseline/manifest.json) は変更せず、
  [新しい2件だけの契約](../../../tests/Shared/LibreOfficeComparisonBaseline/reviewed-pagination/manifest.json) を分離。
  旧manifest・入力・旧PDFの各ハッシュへ結びつけ、他のケース/エンジンには適用しない。
  [回帰結果](regression-report.json) に旧契約に対する不一致も残し、新期待結果への成功と区別した。他の42 PDFは旧契約のまま成功。

Calcと全面一致したわけではない。CalcはヘッダーYが異なり、ページ番号フッターを出さず、
2ページ目にも結合タイトルの背景を出す。製品は2ページ目にその背景を出さない。
文字幅・列境界にも差が残る。これらを理由に参照PDFを修正したり許容値を広げたりしていない。
